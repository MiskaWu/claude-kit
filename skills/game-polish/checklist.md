# 對標清單：評價高的小遊戲做到的事

照影響排。每一條都問：「玩家在**手機上第一次玩**，看得懂、感覺得到嗎？」讀截圖時逐條對，列出落差再挑最大的改。

1. **手機上看得清楚。** 主角與關鍵物件在手機上至少約 60 px。固定鏡頭看全場在桌機還行，手機上主角只剩一點。
   鏡頭跟著事件推近拉遠（規劃時看遠、關鍵那一刻推近），指數平滑、縮放在對數空間內插，速度感才一致。
   可用畫面要扣掉 HUD 與觸控按鈕的高度，主角才不會被按鈕蓋住。
2. **每個重要事件都有手感回饋**，而且好幾層一起來：慢動作、鏡頭或畫面震動、粒子、蓋章大字（「完美！」「翻車！」「誤捐！」）、音效、震動。
   強度跟嚴重度成比例；**好的結果也要有**（叮一聲、和弦、閃綠框），不是只有壞事才有演出。
3. **回饋出現在玩家眼睛看的地方。** 判斷型的遊戲眼睛在卡片和按鈕上，結果就從按下的那顆按鈕飄出來，不要跳在畫面另一頭。
   提示放在發生的地方（主角旁冒「按住 吸附」、落點的影子、擺正後的輪廓），HUD 的字是備援。
4. **心流：讓玩家感覺到自己進入狀態。**
   - 連續做對有遞進的回饋：計數、里程碑大字、音高隨連對升高、到一定連對卡片或畫面發光。
   - 清楚的近程目標：進度條標出下一道門檻（及格、高分），衝過那一下有演出。
   - 節奏有起伏：換段落有號角或提示（但不擋住主要畫面）；最後幾秒有滴答與畫面邊緣的緊張感。
   - 一段一段來：教學一段一段停下來，練完給評語；很不順才建議多練一小段，而且可以跳過。
5. **場景要有自己的設定**，不能只是通用漸層：挑一個具體的地方，遠景分兩層視差，地面有質地。設定從題材本身的世界來。
6. **開場和結算是高潮，不是表單。** 開場要有名字、一句話講完玩法、個人紀錄；結算先給一兩個大數字（從 0 跳上去）、
   破紀錄標記、蓋章，明細收進可以展開的區塊；結算演出也要有聲音。
7. **說明以圖為主、字越少越好。** 規則用「✕ 這樣不行／○ 這樣可以」兩張對照小圖，只畫要看的那一欄；操作用動畫示範，不寫操作說明。
8. **清掉版面雜訊。** 面板打開時收起 HUD、觸控鈕、按鍵說明；矮螢幕上主要按鈕黏在面板底部；用不到的標籤過了就收；兩個提示不要疊在同一處。
9. **音效**：WebAudio 即時合成就夠，不用音檔（也就不碰官方素材）。持續音每幀調音量，一次性音效跟著事件。
   第一次使用者互動才建 AudioContext；選單裡可以關，記住選擇；震動跟同一個開關。
10. **減少動態**（`prefers-reduced-motion`）：關掉閃爍、震動、數字跳動，直接顯示最終值。
11. **手機版面**：面板與按鈕不被擠出畫面或被遮住、文字不溢出（每個語系都看）、不該出現的 HUD 沒露出來。
