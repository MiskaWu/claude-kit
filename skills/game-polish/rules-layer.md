# 規則層：自動玩家與可玩性底線

遊戲核心是**確定性、可重播**的（固定步長、整數或固定的亂數、同一串輸入結果逐位元相同）才做得了這一層。
核心不確定的話，先把它做成確定的（純邏輯、不讀時鐘與 DOM、亂數由種子衍生），這本身就值得。

## 自動玩家

- 自動玩家**只讀狀態、只輸出輸入**，和真人走同一條路（同一個 Session／sim、同一個操作 API）。它不是最佳解，是「一種玩家」。
- **人設**比單一最佳解有用：幾種玩法各跑一批固定種子，看分布。例：
  - 動作類：不操作、一直按、合理玩家（往前看兩步、該擺正時擺正、算剎停距離點火）。
  - 判斷類：亂答狂按 0.1 秒、亂答 0.3 秒、衝很快錯 15%、普通 0.9 秒錯 5%、仔細、高手、
    只懂部分規則的新手（找哪條規則最常害人）、專做某個壞事的人（產生特定演出與隱藏結局）。
  - 每件的判斷時間在平均的 80%～120% 之間抖動；人設的亂數也由（種子, 人設）衍生，同一個人設同一個種子打出來一樣。
- **固定的一批種子**（例如 300 個，用一個常數衍生），每次跑的都一樣，數字才能比較。
- 一支印統計表的指令（例如 `cargo run -p game-core --example personas`）：每個人設的分數平均與最佳、過門檻的比例、評價分布、
  各規則與各段落的出錯率、特定事件的發生次數。調參前後各跑一次比對。

## 用數據調參

- 依統計表的落差改參數，改完再跑一次。例：某款動作遊戲自動駕駛的落點偏離落地區中心 → 移落地區、修評分公式 → 從「良好」到「完美」。
- 參數集中在一份設定檔（「試玩調參只改這裡」）；改了會讓舊紀錄或重播不相容的，升設定的版本號。

## 可玩性底線寫成測試

照「這關打得過、亂玩會輸、重播一致」寫，調參後仍然要綠：

- 亂玩（亂答、亂按、不操作）的結果明顯輸給認真玩的（例如最佳一局不到普通玩家平均的五分之一）。
- 合理玩家打得過、普通玩家多數過及格線、高手有一定比例拿最高評價。
- 只懂一部分規則的玩家輸給全懂的（規則有教的必要）。
- 特定事件在一局裡出現的次數落在設計的範圍（例如「身上那件」一局 3～8 次）。
- 同一個人設、同一個種子，打出來一模一樣；固定步長下結果只由輸入決定，和呼叫節奏無關。
- 測試用較少的種子（例如 60 個）跑得快，統計表用多的。
