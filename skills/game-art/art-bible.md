# 美術規則書範本

game-art 讀的「這個專案的答案」。放在專案 `docs/`（例如 `docs/craft/art-bible.md`），在專案 CLAUDE.md 加一行指過來；
改調色、材質、燈光參數之前先讀這份。

寫法：

- **支柱與色板由使用者拍板。** 你提選項與依據（參考作品、職能研究），不要自己決定風格。
- 每一條附來源，每一條盡量有能量的標準，並寫出用哪個工具量。
- 業界沒有數字的門檻標「提案」。
- 改動照專案既有的決策寫法記錄（日期、誰拍板、理由）。

---

```markdown
# <專案> 美術規則書（art bible）

<起始日期> 起。依 <研究筆記的位置> 寫成；每一條附來源，每一條都有能量的標準（量測：<專案的工具與指令>）。

## 支柱（兩到三條）

每條一句話，加依據。例：「夜為墨底，火為光池」——夜是底色不是黑色，畫面要有三個明度群，火光與主角是最亮的那一群
（依據：Gurney 明度先行；D4 return to darkness）。

## 風格對應渲染參數

| 畫法或風格語彙 | 渲染參數 |
|---|---|
| 例：白描（線細而勻） | 後處理的線寬與濃度 |
| 例：提染（只提亮焦點） | 主角光、焦點加亮 |

## 色板

- **世界（環境）**：每一色寫色相範圍與飽和上限。
- **語意色（環境不准用）**：敵方、主角、掉落、介面各自的色相範圍與依據。
- 環境材質落在語意色相、而且飽和超過門檻的，列出來改。

## 素材統一

所有世界材質經過哪一個上色節點；材質類別有哪些；明度夾在多少、飽和上限多少；
沒歸到類別的素材怎麼處理（應該讓測試失敗，不要靜默保留原色）；角色走哪一層、共用哪些收尾層。

## 量化標準（<截圖解析度>、<固定鏡頭與種子>；標「提案」者為本專案自訂）

| 項目 | 標準 |
|---|---|
| 明度中位數 | |
| 主角對地 | ≥ 3:1 |
| …… | |

## 色彩腳本

每段一張；相鄰兩段在主光溫度、整體明度、點綴色至少一項不同。

## 流程

1. 明度稿：先把明度排好，再談顏色。
2. 色彩：每加一個素材包先指定材質類別，再跑 line-up 截圖與量測。
3. 色彩腳本。
4. 每次改調色參數都用固定鏡頭重拍，數字與並排圖記進 <視覺審查文件>。
```
