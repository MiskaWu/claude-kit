# game-shorts —— 用遊戲畫面做短影音

從一款網頁物理小遊戲的第一批短片帶出來的做法（2026-10）。**這裡只寫做法與檢查點，不寫數字**：
平台規格、安全區、鉤子與留存的基準值、案例，寫在研究文件〈遊戲發行與粉絲經營研究〉的「素材與短影音 › 短影音製作」分頁
（作者的研究未隨本 repo 公開；引用前看查證日期，超過半年的當成要重查）。
發在哪、怎麼量、怎麼命名，照 **game-publish**；這份只管「把片做出來」。

## 0. 先看專案有沒有現成的

開工前在專案 CLAUDE.md、`docs/decisions/` 找「短片」「導演頁」：有的話照它的分鏡資料夾與輸出指令走，只加新分鏡，不另起一套。
沒有就照第 2 節搭管線，搭完把指令寫進專案 CLAUDE.md、架構寫進決策文件。
完整專案的結構：`web/src/video/`（導演頁）、`web/scripts/video/`（虛擬時鐘、輸出、分鏡 JSON），再加一份記下取捨的決策文件。起手的副本在 [templates/](templates/)。

## 1. 原則

- **只用真畫面。** 每一格都是遊戲本身（同一份核心、主迴圈、renderer、特效）跑出來的；字卡上的數字照那一局的真實成績填，
  不寫「99% 的人過不了」這種沒有資料的宣稱——要寫就先從伺服器撈真實比例。重新取景、變速、凍結是剪輯，不是造假。
- **自動駕駛打出來的成功要標「示範」**，用遊戲自己的那個字。失敗的按法可以是劇本，只要真人照按會得到同一個結果。
- **畫面＝系統實際發生的事**（同 game-polish）：疊在上面的裝置鈕讀核心的作動狀態，不是讀劇本說「這時候按了」。
- **先有分鏡再錄。** 分鏡是一份宣告式的 JSON（鏡頭、拍數、字卡、音效點），放進版控；改一句字卡、換一個鉤子都是改資料重出，不是重剪。
- **一次只動一個變數。** 同一支母片換鉤子（前兩秒）出幾個版本，其他不動，才量得出是哪裡起作用（game-publish 第 2 節）。
- **配樂自己合成或用確定授權的。** 平台內建音樂庫對商業帳號有限制，詳情看研究文件。

## 2. 管線

```
分鏡 JSON ─▶ 導演頁（遊戲的核心＋renderer＋錄影鏡頭＋疊加層）─▶ 虛擬時鐘逐幀截圖 ─▶ ffmpeg
                         └─ 同一個離線 AudioContext：遊戲音效＋合成配樂＋剪輯音效 ─▶ 兩段式響度校正 ─┘
```

1. **導演頁**：一個只給錄影用的頁面（不上正式站），直接 import 遊戲的核心、主迴圈、renderer、特效、音效。
   照分鏡一段段播：每個鏡頭＝某條操作劇本的某一段、某個速度、某個取景。切到新的一局時，先不出聲地快轉到切入點。
2. **錄影鏡頭**：遊戲的鏡頭是為了能玩（看全景），直式畫面上主角常常只剩一個點。給 renderer 一個選用的鏡頭參數
   （中心、看得到多高），導演頁照階段跟拍。這是唯一要碰遊戲程式的地方，而且只加一個選用欄位。
3. **主迴圈共用**：遊戲畫面和導演頁用同一份「推進核心、比對前後狀態產生事件、事件交給特效音效」的模組。
   兩邊各寫一份，特效遲早分岔，片子就不再是遊戲真正的樣子。
4. **虛擬時鐘**（範本 `templates/vclock.js`，init script 注入）：接管 `performance.now`、`Date`、rAF、計時器、
   CSS 動畫（`document.getAnimations()` 逐幀定位）、`Math.random`（固定種子）、`AudioContext`（換成同一個離線的，currentTime 跟著走）。
   錄得再慢，片子裡的時間都是均勻的；同一份分鏡出兩次，像素一樣。
5. **輸出**（範本 `templates/render.mjs`）：一支片切成幾段平行截，每段**一個瀏覽器**；另開一頁不截圖、只跑聲音。
   接起來後照研究文件的規格編碼，響度兩段式校正。順手出一張每秒一格的接觸表給自己檢查。
6. **配樂**（範本 `templates/music.ts`）：照分鏡的 BPM 與段落合成；鏡頭長度用拍寫，切點自然落在拍子上；
   撞擊前一拍全停（stop）、撞擊落在 drop 上，是最便宜的張力。

技術細節與踩過的坑見 [pipeline.md](pipeline.md)，搭之前掃一遍。

## 3. 每支片的流程

1. **找素材時刻**：列出遊戲的動詞與「陌生人不用背景也看得懂」的瞬間（例如賽車遊戲：甩尾過彎、飛越斷橋、空中翻正、翻車零件噴飛）。
2. **寫操作劇本**：每條是一種按法（完美、各種錯法、差一點）。先用核心空跑一遍，記下事件時間與成績——分鏡照事件對時，不照秒數猜。
3. **寫分鏡**：照 [storyboard.md](storyboard.md) 挑鉤子、套 beat sheet、寫字卡（所有語系一起寫）。
4. **出片 → 看接觸表 → 抽關鍵幀看全尺寸**：字卡有沒有疊到遊戲自己的字、主角在不在安全區、數字有沒有跳完、片尾乾不乾淨。
   有問題改分鏡重出，不在輸出檔上補。
5. **出各語系**：同一份分鏡換語系重出（字卡、遊戲內的字都會跟著換）。
6. **交付**：成片用 SendUserFile 給使用者看；附上每支的鉤子、長度、借了哪個手法。

## 4. 回報

- 每支片：檔名、長度、鉤子一句話、用了哪幾條劇本與它們的真實成績。
- 實際跑了哪條輸出指令、花多久；有沒有頁面錯誤。
- **沒驗到的寫清楚**：配樂好不好聽、音量平衡、在真機上看字夠不夠大——無頭瀏覽器只量得到響度與峰值。
- 要發佈的話照 game-publish：來源代號、連結放哪、要量哪些數字。
