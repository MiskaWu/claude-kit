# 一頁設計與設計日誌範本

game-design 讀的「這個專案的答案」。專案已經有設計文件（設計憲法、SPEC、design.md）的，**不要另建一份**，
只把缺的欄位（體驗一句話、定位、這一輪的假設與生死判準）補進它既有的結構，並問使用者要不要加。

寫法：

- **體驗一句話、支柱、定位、生死判準由使用者拍板。** 你提選項與依據，問不到的留「未定」。
- 一頁講得完。講不完的功能，多半還不能開工（Librande〈One-Page Designs〉的引申）。
- 標日期；改動照專案既有的決策寫法記錄（日期、誰拍板、理由）。
- 設計日誌是另一份檔案，最新的在最上面（Cook〈Game Design Logs〉）。

---

```markdown
# <作品> 一頁設計

<起始日期> 起。設計日誌在 <路徑>。

## 體驗（🔒 使用者拍板）

- 一句話：玩家要感覺到什麼。寫情緒，不寫功能。
- 主打的享受：從 MDA 八種（感官、幻想、敘事、挑戰、同伴、發現、表達、消遣）挑兩三種，排出主次。
- 定位：要可靠地量出誰最強，還是讓每個人都有好的挑戰？一局多長？失敗多痛？
- 支柱（兩到四條，寫感受）：每個功能都要對得上一條，對不上的砍。

## 核心循環

- 動詞：玩家每幾秒在做什麼。
- 決定：在哪裡做什麼取捨；哪個選項在什麼情境下最好。
- 回饋：做完當下看到什麼；之後怎麼還算數。
- 學習：第 1、10、100 局各在學什麼。
- 新挑戰：學會的東西之後用在哪裡。
- 會重複的（loop）與只用一次的（arc）：拿掉 arc 之後核心還成立嗎。

## 這一輪的假設

- 要回答的一個問題：
- 生死判準（事先寫，不事後補）：
- 怎麼量：自動玩家量什麼（指令）；真人看什麼。

## 不做的事

這一輪刻意不碰的系統，與理由。

## 未定

問不到答案的欄位列在這裡，附要使用者決定的選項。
```

```markdown
# <作品> 設計日誌

最新的在最上面。每條五分鐘讀得完。

## <日期>

- 試玩筆記：誰玩、玩了哪一版；做了什麼、臉上與嘴上的反應（原話）。每個問題附一個提案。
- 量到的：指令、局數、種子、數字。
- 下一步（照影響排）：
- 實驗：這一輪大膽試的東西與結果。
- 決定：誰拍板、理由。
```
