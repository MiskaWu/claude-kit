# 發行設定範本

game-publish 讀的「這個專案的答案」。放在品牌或專案的 repo（同一個品牌底下有多款作品時，放品牌那一層），
在每款作品的 CLAUDE.md 加一行指過來。

寫法：

- 每一條寫**答案、理由、出處**；出處可以是研究文件的分頁，也可以是專案自己的規格或決策文件。
- 已經寫在專案規格裡的（例如隱私原則），**引用條號，不重抄**，免得兩份慢慢分岔。
- 數字不寫在這裡，寫在研究文件；單一作品的決定寫在作品自己的決策文件。
- 負責人改動寫成「**YYYY-MM-DD 負責人拍板**：…」並附理由，被換掉的文字用刪除線留著。
- 問不到答案的留「未定」，不要替負責人補。

---

```markdown
# <品牌> 發行設定

> game-publish 技能讀的 <品牌> 答案。數字在研究文件；單一作品的定位寫在作品自己的決策文件。

## 0. 對外身分
對外用什麼名字、大小寫、哪些字不能出現、能不能自稱官方或工作室。

## 1. 隱私立場
能不能放追蹤像素、能不能做轉換回傳；付費投放因此只能最佳化到哪一步。

## 2. 作品線
有沒有授權或二次創作的作品；每條線在付費廣告、入口站、美術、社群帳號上的差別（做成表）。

## 3. 授權的商業邊界
只有二次創作或授權 IP 的作品才需要：能不能收費、能不能群募、上架商店用什麼名義、標題限制、標示方式。
條文原文放在專案的查證文件，這裡只寫發行時的動作。

## 4. 自有名單管道
現有哪些（email、LINE、Discord、Steam 開發者主頁……）、各自發什麼、怎麼問使用者同意。

## 5. 短連結與來源
對外連結怎麼帶來源；有哪些已知的 App 內建瀏覽器處理。

## 6. 市場與語系
語系、正本語言；每條作品線先打哪個市場、用哪些平台、哪些平台不做。

## 7. 付費
現階段的目的、開投的前提、預算上限、哪些作品不投。
```
