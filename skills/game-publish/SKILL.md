# game-publish —— 遊戲的曝光、轉化與粉絲經營

從兩輪發行研究帶出來的做法（2026-10-20）。**這裡只寫做法與檢查點，不寫數字、不替專案下結論**，三樣東西各有各的家：

| 要找的 | 在哪 |
|---|---|
| 數字：基準值、價格、平台規則、展會日期、案例 | 研究文件（作者的研究未隨本 repo 公開，請換成你自己的研究來源）。引用前看查證日期與標記，超過半年的數字當成要重查 |
| 這個專案的限制與既有管道 | 專案的**發行設定**（第 0 節） |
| 這一款怎麼定位、上哪 | 作品自己的決策文件 |

研究文件裡針對特定品牌的做法是那個專案的應用，別的專案只讀研究本身。

## 原則

- **量不到的實驗不做。** 前提沒接好（第 1 節前三項）就推，等於燒掉流量換不到資料。
- **會用掉就回不來的東西不拿來測。** Next Fest 一款一生一次、商店頁第一印象、發售日。曝光可以重來，這些不行。
- **名單才是資產。** 曝光帶進來的人先留進自有名單，平台的追蹤數是租來的。
- **付費是放大器，不是主路。** 先證明自然流量能把人轉進名單，再花錢放大已經會轉的東西。
- **只看量級差。** 前十篇不下結論；三倍以上才算訊號，兩成的差當雜訊。
- **判斷靠這份技能提醒，不加 hook 擋。**

## 0. 先找發行設定

開工前在專案 CLAUDE.md 找「發行設定」指向的那份（通常在品牌層級的 repo）。照它的答案走；它跟這份技能衝突時以它為準。

沒有的話，先問使用者下面六題，照 [profile.md](profile.md) 的格式建一份，放在品牌或專案 repo，並在 CLAUDE.md 加一行指過去。**答案不要自己補**，問不到的留「未定」：

1. 隱私立場：能不能放追蹤像素、做轉換回傳？
2. 授權限制：有沒有二次創作或授權 IP？指引原文與查證在哪？
3. 自有名單管道：email、LINE、Discord、Steam 開發者主頁，現在有哪些？
4. 短連結機制：對外連結怎麼帶來源？
5. 市場與語系。
6. 付費上限：每月能花多少？哪些作品不准投？

## 1. 每出一款的清單

照順序；**前三項是量測的前提，沒做完不要開始推**。

1. **結算畫面**：主按鈕是「再一局」，第二顆是「分享」。結果卡在結算當下產生靜態圖，連結點開就是同一局挑戰。
2. **第二局率量得到**：讓開局本來就會送的請求帶上「第幾局」，依來源算。這是最重要的一個數字。
3. **每個對外連結都帶得出來源**，照發行設定的短連結機制（命名見第 5 節）。App 內建瀏覽器的坑先處理：LINE 加外開參數；內建瀏覽器裡 Google 登入會失敗，把其他登入方式放前面。
4. **判斷這款屬於哪一條作品線**：發行設定裡有授權限制的作品，哪些平台、付費、入口站不能碰。
5. **選平台**：自站、社群、入口站。入口站可以當免費的原型測試場，但簽獨佔之前停下來問使用者。
6. **素材**：找出遊戲裡「陌生人不用背景也看得懂」的時刻；優先做遊戲內建錄影或回放匯出，乾淨的實機畫面比後製好。
   短影音的製作（分鏡、確定性擷取、剪輯、配樂、多語系輸出）照 **game-shorts** 技能。
7. **名單邀請**：放在破紀錄、上榜這種高峰時刻，不在開場擋人。
8. **有 Steam 版的**：照第 4 節倒推。
9. **記下來**：這款的選擇與理由寫進作品的決策文件；發文紀錄的欄位照第 5 節。

## 2. 每週素材循環

- 每週錄一次，切出一批片段。每週發 1 個新概念，加上週勝出者的換鉤子版；一次只動一個變數，先動開頭兩秒。
  片子怎麼做照 **game-shorts**（分鏡是資料，換鉤子＝改分鏡重出）。
- **主貼文發原生影片，不發純連結。** 連結貼文在多數平台的觸及很差（數字看研究文件「素材與短影音 › 短影音製作」分頁）；連結放留言、個人檔案或置頂，照樣帶來源代號。
- 一支母片做成各語系的 9:16，關鍵畫面放中央 4:5 安全區；字幕燒進去；跨平台錯開一兩天，去掉別家浮水印。
- 主看的是曝光、完播或停留、追蹤增加、到站、第二局率；讚只當參考。
- 不做假遊戲畫面（加註「非實際畫面」也不行）。AI 只用在字幕與翻譯草稿；畫面上用了 AI 照平台規定揭露。

## 3. 外聯（實況主、VTuber、媒體）

1. **先做配信規範頁**：可以直播、可以營利、要不要事前聯絡、建議附什麼標示與連結。沒有這頁，日本實況主多半直接跳過。
2. **挑人**：看平均同時觀看與近期玩過的同類遊戲，不看訂閱數。每人一個專屬來源代號。
3. **信只寫三件事**：免費或一局幾分鐘、可以直接開玩的連結、配信規範頁；再附一個能跟聊天室互動的玩法。
4. **付費合作**：先試最低一級，要求標示 PR。

## 4. Steam 倒推

- **錨點是「發售前最後一場 Next Fest」**。從它往回排：報名截止、獨立的 demo App 上線（至少提前一個月）、商店頁開頁。
- 有確定發售日才進得了個人化日曆；發售前兩三個月公布。
- 第一支預告片要隨便切哪一秒都看得懂（首頁的微預告是從它自動抽的）；截圖至少 4 張標全年齡。
- 商店頁說明寫完整，有因為太簡略被退件的前例。
- 目標數字與現行規則看研究文件的「Steam 願望清單」分頁。

## 5. 命名

- 一則貼文一個代號：`<平台>-<內容編號>-<語言>`，例如 `x-clip01-ja`。沒附連結的貼文也要編，它是紀錄表那一列的名字。
- 品牌底下多款作品共用一張代號表（例如品牌站的 `content/links.toml`）時，**內容編號帶作品名**：`x-rocket01-en`，不是 `x-clip01-en`，否則各款的第一支片會撞號。
- 遊戲要讀短連結轉過來時帶的那個參數（例如 `ref=`）；遊戲自己原本的參數（例如 `src=`）照樣認。名字不一樣，來源就斷在中間，第二局率算不出來。
- 展會、實況主也各一個代號，例如 `event-<展名>`、`streamer-<名字>`。
- 送進 Steam 的 UTM 保持粗粒度：`utm_source` 是平台、`utm_campaign` 是內容編號、`utm_content` 是語言或位置。細粒度留在自家短連結；量不夠的 UTM 組合，Steam 會整列隱藏。

## 6. 什麼時候回頭查研究

平常不重跑研究。碰到下表的情境才查，查完寫回研究文件對應的分頁，標輪次與日期。

| 情境 | 先查什麼 | 寫回哪頁 |
|---|---|---|
| 要對某款作品花錢投廣告 | 該題材在 Meta、TikTok、X 的審核類別（例如金融、類賭博題材） | 付費投放與歸因 |
| 某款作品要開始推 | 競品掃描：同類遊戲在 Steam、入口站、手機上的評論數、價格、標籤、負評重點（格式照「Steam 願望清單」分頁的競品表） | Steam 願望清單，或網頁分發與病毒 |
| 要確認某地區打不打得開網頁 | 用瀏覽器工具跑當地的測速服務，挑當地晚上的尖峰時段 | 市場分頁 |
| 要找廣告前例 | 用瀏覽器工具開 Meta Ad Library 這類要跑 JS 的頁面 | 付費投放與歸因 |
| 要報展會 | 當屆的報名期限、費用、海外社團規定、電源與試玩規定 | 市場分頁 |
| 引用的數字超過半年 | 重查那一條 | 原分頁 |
| 作品資料不足以判斷平台 | 先補作品本身：類型、一局多久、目標玩家 | 作品的決策文件 |

研究的跑法：

- 一次派 2–3 路研究 agent，每路寫明搜尋額度（約 40–50 次）。搜尋額度是共用的，六路同跑會在半途用完。
- 每條主張標【出處】【經驗法則】【推論】【實測】；數字附來源與年份；查不到就寫查不到，不要推測成事實。
- 要跑 JS 或要登入的頁面，研究 agent 抓不到，改用瀏覽器工具。
- 先在研究文件要寫的位置放 pending 區塊，回來後替換；總覽的進度表同步更新。
